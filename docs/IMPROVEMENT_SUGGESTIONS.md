# fnos-qbittorrent 改进建议

本文档汇总了针对当前仓库的可执行优化项，按优先级分为「短期可落地」和「中长期演进」。

## 一、短期可落地（建议 1~2 周内）

### 1. 强化默认安全配置（高优先级）
- 首次安装后引导用户强制修改默认账号密码（当前 README 已提示，但建议在安装流程中技术性约束）。
- 增加 WebUI 暴露风险提示（例如仅允许局域网访问、建议搭配反向代理和 HTTPS）。
- 在文档中增加「安全基线」小节：密码策略、端口暴露建议、权限最小化原则。

**收益**：显著降低弱口令和公网暴露导致的安全风险。

### 2. 增加安装前置检查与错误提示
- 下载目录不存在时，提供更清晰的 UI 级报错文案（包括示例路径格式）。
- 安装时自动检查目录可写权限、端口占用、系统版本、CPU 架构，并给出可操作的修复建议。
- 对「请勿在 WebUI 中修改端口」增加拦截提示（设置检测到变化时回滚并提示原因）。

**收益**：减少安装失败与使用误操作，降低 issue 支持成本。

### 3. 补充“常见问题（FAQ）”文档
建议新增 `docs/FAQ.md`，覆盖：
- iframe 中设置无效的原因与正确操作方式
- 升级后数据恢复排查
- RSS/搜索插件失效排查
- WebUI 无法访问的诊断步骤（端口、权限、日志）

**收益**：提升用户自助排障能力，减少重复反馈。

### 4. CI 增加基础质量门禁
- 对 shell 脚本增加 `shellcheck`。
- 对文档链接做链接有效性检查（可选）。
- 构建产物命名、版本号一致性做自动校验（manifest 与 README 版本号比对）。

**收益**：减少发布前低级错误，提升发布稳定性。

---

## 二、中长期演进（建议 1~2 个月）

### 1. 配置管理统一化
- 当前端口、UI 类型、下载目录等配置分散在安装参数与应用设置中，建议沉淀统一配置层（含校验逻辑）。
- 引入“配置迁移”机制，保证升级后配置可兼容历史版本。

**收益**：降低升级兼容风险，减少配置项新增时的维护复杂度。

### 2. 日志与诊断能力增强
- 统一日志目录与日志轮转策略。
- 提供“一键导出诊断包”脚本（版本信息、配置摘要、关键日志）。
- 文档中明确如何定位安装/升级失败日志。

**收益**：显著提升问题定位效率，便于社区协作排查。

### 3. 发布流程规范化
- 建议建立 `CHANGELOG.md`，采用固定格式（Added/Changed/Fixed）。
- 发布时自动生成 release note，并附带升级注意事项。
- 明确 ARM64/AMD64 支持策略，避免用户误装。

**收益**：提升版本可追踪性和用户升级体验。

### 4. 自动化测试补强
- 增加最小化冒烟测试：安装后检查服务启动、WebUI 可访问、端口可配置。
- 增加升级回归测试：模拟「保留数据」路径，验证种子和配置恢复。

**收益**：降低回归风险，尤其是升级路径的稳定性风险。

---

## 三、建议执行顺序（Roadmap）

1. **安全和安装前置检查**（高收益、低改造成本）
2. **FAQ 与诊断文档完善**（快速改善用户体验）
3. **CI 质量门禁与版本一致性校验**（降低发布风险）
4. **配置统一化与测试体系建设**（中期工程化能力）

---

## 四、衡量改进成效的指标（建议）

- 安装失败率
- 升级失败率
- 因端口/UI配置误操作导致的问题占比
- issue 首次响应到定位耗时
- 重复问题（FAQ 覆盖后）占比

通过以上指标可持续验证优化是否有效，并用于迭代优先级调整。
